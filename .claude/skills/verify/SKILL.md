# 배포 전 검사

## 규칙

**`npm run verify` 가 통과하지 않은 것은 커밋하지도 배포하지도 않는다.** 예외 없다.

이건 기억에 맡기지 않는다. 빠져나갈 길을 막아 두었다:

- **없는 이름 검사가 `scripts/build.mjs` 안에 있다.** 굽기 전에 돌고, 걸리면 번들이
  아예 안 나온다. `dist/bundle.js` 를 만드는 길이 여기 하나뿐이라, 검사를 건너뛴
  번들은 존재할 수 없다.
- **`pre-commit` 훅**이 빌드+스모크를 돌린다(3초). 깨진 것은 커밋되지 않는다.
- **`pre-push` 훅**이 전체 검증을 돌린다. 푸시가 곧 배포라 여기서 막는다.
- 훅은 `.githooks/` 에 커밋되어 있고 `npm install` 이 `core.hooksPath` 를 걸어 준다.
- 화면 일부가 갱신을 멈추면 **빨간 띠로 화면에 뜬다.** 굳은 화면은 원인을 말해 주지
  않지만, 못생긴 띠는 말해 준다.

`--no-verify` 로 넘길 수는 있다. 그러려면 스스로 그렇게 정해야 한다 — 모르고
지나가는 일은 없다.

빌드가 되는 것은 아무 보증이 아니다. 이 게임은 esbuild IIFE 라 **모르는 이름을
전역 참조로 두고 조용히 넘어간다** — 임포트를 하나 빠뜨려도 번들은 멀쩡히 만들어지고,
첫 화면도 멀쩡히 뜨고, 그 이름을 쓰는 패널만 죽는다. 여태 네 번 물렸다:
`addManaLog`, `soulGainLog`, `chalGoalLog`, `budget2Log`.

## 절차

```bash
npm run verify     # 빌드 → 없는 이름 → 스모크 → 하네스 8종 → 글자 검사
```

통과하면 커밋하고 배포한다. 배포는 GitHub Pages 빌드가 **`built <내 커밋>`** 을
찍을 때까지 기다려서 확인한다 — 푸시했다고 배포된 것이 아니다.

```bash
gh api repos/advanced-rising/mana-tower/pages/builds/latest --jq '.status+" "+.commit[0:7]'
```

## 무엇이 무엇을 잡는가

| 검사 | 잡는 것 |
|---|---|
| `nonames` | 임포트를 빠뜨린 자리 (tsc TS2304/TS2552). 위의 네 번을 잡는 검사다 |
| `smoke` | 페이지가 아예 안 뜨는 것 |
| `numlint` | 축약 안 된 날숫자가 화면에 나오는 것 |
| `numaudit` | 비용 수학, 묶음 구매, 잔액, 이중 적립 |
| `tabsweep` | 탭마다 이미지 깨짐·중복, 긴 숫자 |
| `infsweep` | 유한한 값이 ∞ 로 새는 자리 |
| `matflow` | 돌파 뒤 재료가 실제로 흐르는가 |
| `stalem` | **배율 캐시가 낡는 자리** |
| `updthrow` | **화면 갱신이 조용히 멈추는 자리** |
| `invariants` | 한 시간 플레이 불변식, 장비가 장마다 갈리는가 |
| `textscan` | 빈 라벨, 배경에 묻힌 글자, 잘린 글자 (데스크톱·휴대폰) |

하나만 돌리려면 `node scripts/verify.mjs stalem` 처럼 이름을 준다.

## 이 검사들이 왜 생겼는지 — 되풀이하지 말 것

새 검사를 만들 때마다 **먼저 일부러 버그를 되살려 검사가 실제로 잡는지 확인한다.**
잡지 못하는 검사는 통과했다는 거짓 안심만 준다. 실제로 겪은 일이다:

- **번들이 낡은 채로 검사가 통과했다.** `verify` 가 빌드를 안 하고 옛 번들을 검사해
  "통과" 라고 답했다. 그래서 지금 `verify` 는 반드시 먼저 빌드한다.
- **화면이 조용히 멈췄다.** `refresh()` 가 `try{u()}catch{}` 로 예외를 삼켜서,
  패널 하나의 숫자가 굳고 라벨이 빈 채로 남는데 아무 표시가 없었다. 지금은
  `updFails` 에 남기고 `updthrow` 가 읽는다.
- **배율 캐시가 낡았다.** `mSignature()` 가 '틱이 바꿀 수 있는 입력' 을 손으로 적은
  목록이었고, 아이템 여섯 갈래가 빠져 있었다. 숫자가 멈춰 있다가 환생을 누르면
  되살아났다 — 돌파 횟수는 목록에 있었으니까. 지금은 목록을 적지 않고
  **computeM 이 읽는 창고를 그대로 훑는다.** 손으로 적는 목록은 반드시 뒤처진다.
- **하네스가 탭을 안 바꾸고 있었다.** `TAB_KEYS` 는 단축키('1','2'…)이고
  `switchTab` 은 탭 **id** 를 받는다. 키를 넘기면 조용히 되돌아나간다 —
  검사가 도는 척만 하고 있었다. 탭을 돌 때는 `G.TABS` 의 `t.id` 를 쓴다.
- **부하로 잘린 검사를 실패로 세면 안 된다.** 하네스마다 있는 `--virtual-time-budget`
  은 '게임 시간을 얼마나 굴릴지' 이지 '몇 초 안에 끝내라' 가 아니다. 그것을 실제 시간
  제한으로 쓰면 기계가 바쁠 때 멀쩡한 검사가 잘려 재시도로 들어가고, 오십 초짜리
  검증이 십 분을 넘긴다. 실제 시간 제한은 '진짜로 멈춰 선 것' 만 잡으라고 있으니
  넉넉해야 한다. 같은 이유로 `__game 없음` 은 고장이 아니라 크롬 넷이 함께 뜨느라
  부팅이 늦은 것이다 — 재시도 대상이지 실패가 아니다.
- **시계가 가상이다.** 하네스는 `--virtual-time-budget` 아래서 돌아
  `performance.now()`/`Date.now()` 가 0 으로 읽힌다. **하네스 안에서 시간을 재지 마라.**
  시간 대신 성질을 재라 — 예를 들어 "가만있는 600틱 동안 서명이 흔들린 횟수".

## 느리다는 말이 나오면 — 재고 나서 고친다

```bash
node scripts/profile.mjs      # 진짜 시계로 어디에 시간이 드는지
```

하네스는 가상 시계 아래서 돌아 시간을 못 잰다. 그래서 이 프로파일러만은 가상 시간을
쓰지 않고, 번들을 **동기로** 불러 load 이벤트 전에 측정을 끝낸다.

2026-08 후반부 상태(항목 422개·깊이 8e10)에서 잰 값 — 새 수치는 이것과 견줘 본다:

| 재는 것 | 값 |
|---|---|
| 한 프레임 (tick+refresh) | 0.4ms — 가장 무거운 탭에서도 2.3ms (60fps 예산의 14%) |
| 배율 접기 `computeM()` | 0.32ms |
| 서명 `mSignature()` | 0.012ms (접기보다 26배 싸다 — 조건부 recalc 이 값을 한다) |
| 세이브 11.3KB · 직렬화 | 0.09ms |
| 오프라인 복구 30일치 | 0.3ms |
| `render()` 호출 빈도 | 1초에 0회 (탭을 바꿀 때만) |

**그래서 "느리다" 는 말이 나오면 산술이 아니라 멈춘 자리를 의심한다.**
실제로 "먹통" 으로 보고된 것은 전부 성능이 아니라 버그였다 — 낡은 배율 캐시와
임포트 빠뜨린 패널. 둘 다 화면이 그 자리에 굳는 모양이라 느린 것처럼 보인다.

라이브러리를 들이기 전에 이 표를 먼저 본다. 큰 수 라이브러리(break_infinity 등) 는
여기서는 **후퇴**다 — 그쪽은 1e(9e15) 언저리에서 막히는데 이 게임은 ee333, 곧
10^(10^333) 을 다룬다. 지금의 로그 산술이 그 위에서 도는 유일한 방법이다.

가장 무거운 자리는 업적 탭(노드 3638개·이미지 573개, 다시 그리는 데 2.8ms)인데,
매 프레임이 아니라 탭을 바꿀 때 한 번이다.

## 검사가 일을 했다는 증거 — COVER

**일을 하나도 안 하고 통과하는 검사가 가장 위험하다.** 하네스 둘이 탭을 하나도 안
밟은 채 "0건" 을 찍고 있었다. 그래서 하네스는 얼마나 일했는지도 적는다:

```
COVER 탭방문=14 굴림=14 memo검사=1397
```

`verify` 는 이 중 **하나라도 0 이면 통과로 치지 않는다.** 새 하네스를 만들면
COVER 줄을 반드시 넣어라 — 무엇을 몇 번 봤는지가 "문제 0건" 보다 먼저다.
실제로 이 규약을 넣자마자 `memo검사=0` 이 걸렸다. 그 검사는 그때까지 아무것도
들여다보지 않고 있었다.

## 새 버그를 만나면

고치기만 하고 끝내지 않는다. **그 부류를 잡는 검사를 하나 만들어 `scripts/verify.mjs`
의 `HARNESS` 에 넣는다.** 하네스는 `tools/*.html` 로 `index.html` 의 `</body>` 앞에
끼워져 진짜 게임 위에서 돌고, 결과를 `<pre id="TESTOUT">` 에 적은 뒤 `DONE` 으로 끝낸다.
`DONE` 이 없으면 도중에 죽은 것이라 실패로 친다. 문제는 `[!]` 로 적고,
마지막 줄에 `=== … N건 ===` 으로 세어 준다.

게임 내부는 `window.__game` 하나로 열려 있다 (번들이 IIFE 라 안쪽 이름이 안 보인다).
